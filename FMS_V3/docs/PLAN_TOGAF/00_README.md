## 為什麼要有這份計畫 (它補了 08 的什麼)

`08_開工設計.md` 是**技術設計** (DDL / Queue / Worker), 但沒回答:
1. **誰負責哪一塊** (權責 / RACI) — DBA 還是 SA? 出錯誰值班? 切換誰拍板?
2. **策略層依據** — 為什麼做、成功長什麼樣、KPI 是什麼
3. **查核制度** — 每階段「憑什麼說做完了」, 測試資料誰交付、放哪

本計畫依 ADM 分層補齊, **設計細節不重抄**, 一律引用 08 / 03 / 07。

## 軟體架構工程師的最短路徑 (「開始寫」從這進)

1. 讀專案根 `CLAUDE.md` → [`../99 ADR`](../99_決策紀錄_ADR.md) (決策) → [`../08 開工設計`](../08_開工設計.md) → 本目錄 [`01`](01_PhaseA_願景與策略.md) (你的 RACI 角色) → **[`06`](06_PhaseEF_遷移計畫_WBS.md) (你的 WBS 任務)**
2. 第一週動工項 (預設起手式, 依專案微調):
   - **[WP0-T1](06_PhaseEF_遷移計畫_WBS.md#wp0--治理啟動-w1)** Git 初始化 + 基線 tag `baseline-asis` (乾淨 clone 可編譯、grep 無帳密)
   - **[WP0-T3](06_PhaseEF_遷移計畫_WBS.md#wp0--治理啟動-w1)** 帳密債務盤點 → 所有硬編碼帳密改走 secrets manager
   - **[WP1-T2](06_PhaseEF_遷移計畫_WBS.md#wp1--基準量測-w1-w2)** 現況效能基準 (p50/p95/p99, 尖峰吞吐) — 沒基準就無從證明重構沒劣化
3. 每個任務做完, 以 `06` 表列的**查核點**自檢並附**測試資料交付**, 才算 Done (定義見 [`07`](07_PhaseGH_實作治理與測試.md) §2)
