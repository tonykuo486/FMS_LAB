# ADR — 架構決策紀錄(FMS_V3,你的設計決策)

> **ADR(Architecture Decision Record)=「為什麼這樣設計」的存摺。**
> 程式碼會說你做了什麼,只有 ADR 說得出**為什麼**——半年後的你、接手的同學、
> 協作的 AI 助手都靠它。每條=背景→選項→決定→代價,五行內寫完。
>
> **驗收建議**:整個專案至少 2 條你自己的真實決策(抄 ADR-0 的格式);
> 「沒有任何決策」的專案不存在——只有沒記下來的決策。

---

## ADR-0(示範):排程衝突檢核放哪一層?

- **日期**:2026-08-25|**狀態**:✅ 示範(這條是教材給的,你的從 ADR-1 開始)
- **背景**:TASK-6 不可重疊。檢核放前端?service?資料庫?
- **選項**:A 前端擋(UX 好但繞得過)/B service 層查詢檢查(邏輯清楚但有 race)/
  C 只靠 DB 約束(絕對安全但錯誤訊息難看)
- **決定**:**B+C 雙層**——service 層檢查給人話錯誤訊息(TECH-10),
  DB `EXCLUDE` 約束當最後防線(SDD §5:應用層檢查有 race,資料庫約束才是底)。
- **代價**:同一規則寫兩處,改時要同步——用測試釘住(兩併發一成功一失敗)。
