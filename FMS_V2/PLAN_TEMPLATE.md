## 標準 WBS 8 層框架（每個 Phase 的子任務分解參考）

> 每個 Phase 按需選用以下 WBS 類型，不需要每個 Phase 都用全 8 層。

```
WBS 1: 基礎設施與依賴
  ├── 環境設置（本地 / CI / 生產）
  ├── 依賴版本升級和鎖定
  └── 配置初始化（環境變數、Secret）

WBS 2: 核心接口與適配
  ├── 定義接口（Interface / Protocol / Contract）
  ├── 實現適配器（Adapter / Wrapper）
  └── 更新 Registry / Factory

WBS 3: 安全與授權
  ├── 認證機制（Auth）
  ├── 授權檢查（Permission / RBAC）
  └── 審計日誌（Audit Log）

WBS 4: 狀態與持久化
  ├── 數據模型設計
  ├── 持久層實現（DB / Cache）
  └── 數據一致性保證

WBS 5: 核心業務邏輯
  ├── 主流程實現
  ├── 邊界情況處理（Edge Cases）
  └── 性能優化

WBS 6: 外部接口集成
  ├── API 端點（REST / GraphQL / WebSocket）
  ├── 前端/客戶端集成
  └── 第三方服務（支付 / 通知 / AI 模型）

WBS 7: 測試與驗證
  ├── 單元測試（Unit Tests）
  ├── 集成測試（Integration Tests）
  └── 端到端場景驗證（E2E Scenarios）

WBS 8: 文檔與部署
  ├── API 文檔（Swagger / OpenAPI）
  ├── 架構決策記錄（ADR）
  ├── 運維手冊
  └── 變更日誌（Changelog）
```

## 使用說明（初始化後刪除）

### 新項目 init 流程

```bash
# 1. 複製兩份模板到新項目
cp CLAUDE.md          [new-project]/CLAUDE.md
cp PLAN_TEMPLATE.md   [new-project]/docs/plan/[PROJECT_NAME]-實施計劃.md

# 2. 建立完整目錄結構
mkdir -p [new-project]/{tasks,docs/plan,src}

# 3. 建立任務管理三文件
touch [new-project]/tasks/research.md   # Rule 0 產出：深度研究成果
touch [new-project]/tasks/todo.md       # Rule 1 產出：任務計劃（可勾選）
touch [new-project]/tasks/lessons.md    # Rule 3 產出：累積教訓庫

# 4. 在 CLAUDE.md 填寫 Project Context（必填）
#    - 項目名稱、技術棧、構建/測試/Lint 指令
#    - 填完後刪除提示框

# 5. 在 PLAN_TEMPLATE.md（已重命名）
#    - 填寫項目概覽表格
#    - 刪除不需要的 Phase（保留架構）
#    - 補充第一個 Phase 的詳細 WBS

# 6. 告訴 Claude Code（遵循 7 大核心 Workflow）：
#    「請深入地 (deeply) 閱讀項目結構，理解其複雜之處 (intricacies)，
#      將發現寫入 tasks/research.md，
#      然後閱讀 docs/plan/[PROJECT_NAME]-實施計劃.md，
#      幫我規劃 Phase [N] 的 WBS 並寫入 tasks/todo.md，確認後開始實施。」
```

### 文件職責分工

| 文件 | 職責 | 更新頻率 |
|------|------|---------|
| `CLAUDE.md` | 工程規範（永久有效） | 低（規範確定後少改） |
| `MEMORY.md` | Claude 工作記憶（自動） | 高（每次對話可能更新） |
| `docs/plan/[PROJECT].md` | Phase 規劃與進度 | 中（Phase 完成後更新） |
| `tasks/research.md` | 深度研究成果（Rule 0） | 每個新任務前寫入 |
| `tasks/todo.md` | 當前任務清單（Rule 1） | 高（每次任務更新） |
| `tasks/lessons.md` | 累積教訓（Rule 3） | 中（被糾正後立刻更新） |
